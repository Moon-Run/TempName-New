## 固定实验规则

1. GPU 作业使用普通 `gpu_a800` 队列，通过 `sbatch` 提交；不占用已有作业，不使用优享队列。
2. 登录节点只做编辑、检查和编译，编译并行数不超过 2；计算节点不联网安装依赖。
3. 保存源码提交、实际构建的哈希、GPU UUID/拓扑、软件版本、所有 rank 的原始结果及作业退出码。
4. M/N/K 明确区分全局与局部：每 rank 的输入为 `[M,K/TP]`，权重为 `[N,K/TP]`，输出为 `[M/TP,N]`。
5. profiler、插桩与正式性能计时分开；禁止将 profiler 时长直接替代无插桩端到端时长。
6. 不直接比较不同 GPU 的未校准时钟，不将发送端完成 store 等同于接收端数据可用。
7. 原始环境和二进制放在忽略的 `outputs/`；第一阶段数据、trace 和日志保存于 `logs/a800/phase1/<job_id>/`，可复跑脚本放在 `tools/a800/`。

## 阶段 1：复测基线与粗粒度耗时定位（phase1）

**目标：** 确定当前噪声范围、计算窗口变化的影响，以及当前路径的 kernel 构成。保持调度和精度不变。

**实验：**

- 保留 TP=2、A800/NV8、BF16/RCR、原始 Flux swizzle，以及 test1 的通信选项。
- 测试 M∈{1024,4096,8192}、N=4096、全局 K∈{2048,8192}，共六组 shape。
- 每组先以三个种子，在两个 rank 上分别对照 BF16 GEMM+NCCL RS 和 FP32 参考结果，使用 `atol=rtol=0.02` 的组合容差。
- 无 profiler 时重复 12 轮，每轮预热 20 次、计时 100 次；交替 Flux/基线顺序，记录每个 rank 的平均 GPU 延迟。每轮取较慢 rank，再统计中位数、IQR、CV、最小/最大值。
- 对 M=4096 的两个 K 进行独立 profiler 采样；保留 CUDA kernel 名称、时长、stream 和调用计数。识别融合 GEMM/远端写入、全局 barrier、最终归约，以及未分类 kernel。
- 比较相同迭代数下 profiler 开启/关闭的 CUDA Event 耗时，量化采样扰动。kernel 自身时长不能解释为纯链路传输时间；kernel 间空隙也不能自动归因于网络等待。

**产物：** `baseline.json`、`summary.csv`、`kernel_summary.csv`、原始 trace、硬件与 Slurm 记录、结果报告。

**验收：** 所有正确性检查通过，六组 shape 均有完整的 12 轮双 rank 数据，profiler 含实际 GPU kernel。CV>5% 的配置标为波动较大，后续小幅加速需重新验证；5% 是本项目预设的筛查阈值，并非统计显著性结论。阶段报告必须明确可确定的事实和仍未能归因的现象。

**入口：** 在项目根目录先运行 `mkdir -p logs/a800/phase1`，再运行 `sbatch tools/a800/phase1.sbatch`。复用 test1 已构建环境；新克隆仓库须先准备对应依赖和隔离构建。

## 阶段 2：少量 tile 的依赖与到达剖析

**目标：** 判断最后贡献到达者是否稳定、是否可预测，以及它是否影响全算子尾部。

- 先定义输出 tile、源 rank、目标 rank、Stream-K 局部贡献等标识，避免把 CTA 结束当作整个输出 tile 已完整产生。
- 只对少量 tile 记录贡献准备、发布、接收端观察和最终消费事件；区分本地贡献与远端贡献。
- 采用同一接收 GPU 的时基或经校准的跨 GPU 时基；发布/消费协议必须满足数据可见性，测量线程不得改变原有同步正确性。
- 比较带采样和不带采样的延迟，并改变采样率检查扰动。当前 NVLink epilogue 并不存在可直接分开的独立发送队列，不强行把每次访问拆成五段“精确”时间。
- 输出按 tile/rank 的时间分布、最后到达者频率、join skew，以及与整体尾部的关联。

**验收：** 时间戳语义可解释、采样扰动可量化；能判断瓶颈更接近生产不均、远端访问/接收争用、全局同步还是最终归约。若证据不支持关键贡献假设，先修改模型。

## 阶段 3：仅 BF16 的静态 tile 重排

**目标：** 证明重排能够改善完整 GEMM-RS，而非只让 skew 变小。

- 固定 GEMM tile/hparams、精度、归约实现、输入和 TP，对比原始 Flux、远端优先、按目标分区交替三种逻辑映射。
- 实际入口是 NVLink 的 `ThreadblockSwizzleStreamKRankOffset::get_tile_offset`，不能误改 PCIe 专用调度器。
- 映射保持双射，覆盖边界 tile；考虑 Stream-K 的任务分解与工作区索引。逻辑顺序不承诺硬件完成顺序。
- 同时测端到端时长、融合 kernel 时长、缓存/访存影响和阶段 2 的指标。避免通过推迟快贡献来人为降低 skew。
- TP=4 时按一个本地分区、三个远端分区组织比较，不沿用固定 1:1 的本地/远端比例。

**验收：** 正确性通过；收益在重复实验中超过测量波动，并能解释收益来源；负收益 shape 同样保留。

## 阶段 4：压缩成本与误差预算

**2026-10-03代码推进：** 按用户最新要求，在等待4卡/8卡资源期间开发独立的“原始Flux映射 + TACO全量远端压缩”baseline，不加入重排或选择性量化；实现、独立构建与验收边界见 [base-phase4.md](base-phase4.md)。历史“暂不进入阶段4”的记录保留为当时决策，不覆盖此次明确授权。GPU正确性与收益仍待实测。

**目标：** 在真实 tile 尺寸上判断低精度传输是否具有可实现的净收益。

- GEMM 仍使用 BF16，仅研究输出贡献的通信编码；不能把通信 FP8 与 FP8 Tensor Core GEMM 混为一谈。
- 比较 BF16 写入/传输，与求 scale→Q→FP8 字节传输→DQ→归约。明确格式、scale 粒度、饱和/舍入策略、布局与对齐。
- A800/SM80 上实测转换成本，不套用更新架构的硬件 FP8 转换性能。
- 分别测隔离通信和与 GEMM 并发的情况；包含元数据、额外 HBM 访问及计算资源争用。
- 用 BF16 基线和 FP32 参考记录 max-abs、relative-L2、饱和比例，预先定义误差预算。

**验收：** 找到能够重复获益且误差可接受的尺寸/场景。若 Q/DQ 与干扰抵消字节节省，则保留 BF16，暂不进入复杂选择器开发。

## 阶段 5：选择性压缩与重排联合策略

**到达优先叠加与Megatron量化基线结果：** 远端＋到达优先＋选择性量化相对远端＋融合选择性量化为+0.080% / +0.014%（未确立两轮可重复且区间不跨零的差异）；交替＋到达优先＋选择性量化相对交替＋融合选择性量化为-1.286% / -1.318%（两轮均更慢，区间上界均为负）；Megatron＋张量TACO量化相对原始Megatron为-49.145% / -49.290%（两轮均更慢，区间上界均为负）。完整十二组重新配对计时与局限见[base-phase5.md](base-phase5.md)。

**完整step结果（2026-10-03）：** 远端＋融合选择性量化相对远端＋融合全量量化为-0.166% / -0.142%（两轮区间均为负，重复更慢）；交替＋融合选择性量化相对交替＋融合全量量化为+1.296% / +1.197%（两轮区间均为正，重复更快）。远端＋融合选择性量化相对原始Flux为-4.288% / -4.236%；交替＋融合选择性量化相对原始Flux为-2.762% / -2.755%。完整数值、区间和局限见[base-phase5.md结果](base-phase5.md)。本次完成首版实现和对比，不将负收益配置标为性能验收通过。

**2026-10-03实施更新：** 本阶段已从设计推进到首版实现。仅MLP、attention原始Flux、无到达优先叠加；在各自基础顺序的校准中选取两遍均近临界的尾部候选，每来源量化预算最多25%，未选中贡献保留BF16。共享冻结mask决定发送格式与接收解码，沿用phase4 v2融合kernel。具体九组、输入数据、实际选择比例、正确性和完整step结果以[base-phase5.md](base-phase5.md)为准；尚不把首版候选规则称为已完成净收益模型或迭代自适应。

**目标：** 用低开销策略决定压缩哪些贡献，检验相对全量压缩的价值。

- 首先离线估计策略，避免引入逐 tile 的在线复杂决策。收益模型包含元数据、Q/DQ、访存和对其他 tile 的干扰。
- 精度选择必须与接收端格式/scale/完成标记协议一致；解码后以明确精度累加。
- 选择发生变化后重新估计关键贡献；限制策略迭代次数，考虑多个共同临界贡献及接收端争用。
- 消融：原始 Flux、仅重排、全量远端压缩、仅选择性压缩、重排+选择性压缩；必要时加相同比例的随机选择对照。

**验收：** 联合策略在误差预算下改善端到端性能，且优于其简单组成部分；报告决策开销、压缩比例、失效场景。

### 融合 kernel、同步与最终归约

以下仅为 M=N=4096 的独立 profiler 诊断；数值范围是两个 rank 各自 20 次调用的平均时长，并非置信区间。见 [stage_summary.csv](../../../logs/a800/phase1/178412/stage_summary.csv)。

| 全局 K | 融合 GEMM/远端写入（μs） | IPC barrier（μs） | 最终本地归约（μs） |
| ---: | ---: | ---: | ---: |
| 2048 | 198.25–201.55 | 11.66–12.85 | 53.60–54.14 |
| 8192 | 560.05–567.35 | 11.44–18.35 | 53.56–54.81 |

- 每次还有约 1.8 μs 工作区 memset，以及约 6.8–7.2 μs 的 GPU activity 间隙。间隙未被归因为网络等待，可能包含主机提交与其他执行间隔。

- 当前路径仍是融合 kernel→全局 IPC barrier→本地归约。提早产生某些 tile 不会自动绕过全局依赖；重排是否缩短完整算子，必须实测。

- profiler 启动同步中一个 rank 的 NCCL barrier 达到 35.6 ms；它位于正式 forward 循环之前，已排除，不能作为 tile straggler 或通信尾部的证据。

**目前已经证明：** 该 BF16 路径正确且可重复计时，两个主研究 shape 足够用于下一轮诊断，末尾存在独立归约。

**目前尚未证明：** 最后到达者具有稳定规律、join skew 是端到端瓶颈、远端优先/交替策略有收益、FP8 的字节节省能覆盖 Q/DQ 和资源干扰。

## 阶段 2 实测更新（2026-10-01）
