## 两种“窗口”与置信区间

- **计时窗口**：某一种策略启动一组新的4-rank进程，固定初始化与输入，预热10步后连续计时20个完整optimizer step；取4 rank中最慢的窗口总时长，除以20得到ms/step。预热耗时不进入统计。
- **配对块**：每种策略各运行一个计时窗口，形成同块对比；轮换执行位置，减轻温度/频率或系统负载随时间变化的影响。本次4组每轮8块；上一轮3组每轮6块。
- **tile重排窗口**：每个目标分区16个合法tile槽位，约束离线排序可移动的范围；与20步计时窗口无关。

上一轮MLP-only相对Flux的`+0.097% [−0.006%, +0.212%]`包含两个不同统计量：`0.097%≈0.10%`是全部配对块得到的点估计；括号是配对块bootstrap的95%区间。`0.212%`是区间上界，不是实测最大窗口收益、也不是点估计，更不是从0.212%降到了0.10%。区间不是取上下界的简单平均。

令每块候选与基线的耗时比为`r_b=T_candidate,b/T_baseline,b`，报告点估计为`100×(1−exp(mean(log(r_b))))`。固定随机种子，对整块配对数据有放回重采样10000次，每次重算同一指标，以2.5%与97.5%分位数为区间端点。重采样单位是配对块，不把同一窗口20步冒充20个独立样本。由于该区间跨过0，数据仍容许轻微退化或轻微加速，不能认定稳定正收益；它也不保证下一次运行落在此范围内。

## 1. 查到了什么，改了什么

### 离线“优先最晚 tile”

已同步修正 [TP4 plan.py](../../../tools/a800/arrival/plan.py) 和 [TP8 plan.py](../../../tools/a800/arrival8/plan.py)。

- **旧分数优化了滞后差，而非最晚 tile。** `A(r,t)−max(other)` 很大，可能只是一个很早完成但偏斜大的 tile。v2默认 `--score tail`：每次采样先计算 `a(r,t)=(max_fragment observed_ns − receiver.local_markers[0])/1000`，再取两次训练采样的 `max_r a(r,t)` 中位数作为 tile 分数。仅在同一接收目标分区内比较，不跨GPU比较绝对时钟，也不把不同次调用的绝对时间戳混排。
- **旧中位数会掩盖最后来源不一致。** v2要求来源在两次训练中都满足 `max(a)−a(r) ≤ 2×本次最大轮询周期`，允许多个近似并列来源。另保留 `--score gap` 消融，要求同一来源两次都以大于各自不确定性的差距最后到达，再取滞后中位数。它与历史v1结果不同。
- **没有可信信号时，旧代码强制要求非恒等映射并报错。** 现在允许保持基础顺序，输出 `identity_fallback`；该shape的device查表分支省略。等分稳定排序，零分tile保留相对次序，但仍可能被正分tile后移。
- **输入与统计口径更严格。** 检查完整来源×8个fragment、重复pass/tile、轮询周期、截断/超时和本次起点；检查基础映射的索引、坐标双射与目标分区。plan记录schema、评分方式、生成器哈希、有效/准入/留出样本数与基础顺序审计。构建拒绝旧schema及拟合后已变化的生成器。

仍采用每目标分区16个槽位的窗口，保持原槽位目标分区。交替时窗口实际跨越约 `16×TP` 个全局槽位，并非16个全局槽位。新分数是一次冻结的近临界尾部启发式，尚无被后移tile代价、重排后迭代或低扰动保证。留出集只统计“训练准入来源集合是否包含可分辨的最后来源”；集合变大可能提高命中率，**它不是尾部排序准确率，也不是加速证据**。

### 远端基础、交替与 Stream-K

`remote_first` 的实际代码为 `m=(base_m + tiled_m/TP×(rank+1)) % tiled_m`。本轮确认它是循环分区偏移；column-major或cohort遍历可能提前穿插本地tile，不能称为严格“全部远端在前”。历史二进制与数值继续按这个定义解释；新增 `base_mapping_audit` 明确记录首个本地槽位、最后远端槽位及是否满足严格远端在前，并修正构建脚本的误导注释。若要测试严格远端优先，应作为新基础重新校准、单独出表，不能拿旧 `remote_first` 数据代替。

`interleaved` 的 `destination=(tile_idx % TP + rank) % TP` 在已支持shape上覆盖全部目标分区：TP4为本地1/4、远端3/4，TP8为本地1/8、远端7/8，不是固定本地/远端1:1。拟合仅在同目标槽位窗口内置换，保持这个节奏。含填充cohort槽位的配置继续拒绝，不宣称任意shape可用。

核查了 [swizzle](../../../src/gemm_rs/tile_scheduler/threadblock_swizzle.hpp) 和 [Stream-K调用点](../../../src/gemm_rs/cutlass_impls/sm80/gemmk_universal_with_visitor_streamk.h)：生产与归约都以相同逻辑tile索引调用映射，工作区与依赖索引仍用逻辑索引；本轮未发现重排只作用于生产者而破坏归约配对的问题。映射顺序不保证CTA实际完成顺序，仍须运行时正确性及kernel检查。

### 算子与整步计时

- 算子测的是完整 `GemmRS.forward`，包含其同步与最后归约；逐trial取全部rank最大持续时间，然后做窗口中位数与同块配对比值。未发现只计GEMM、漏掉RS的边界问题。
- 修正 [算子worker](../../../tools/a800/arrival/operator_worker.py) 及其生成源：开始/结束CUDA Event在测量前预先创建并记录，复用到每个trial；barrier后等待GPU再记录start，避免惰性事件初始化落入测量窗口。
- 修正 [算子汇总](../../../tools/a800/arrival/summarize_operator.py) 和 [模型汇总](../../../tools/a800/e2e/scale/summarize.py)：取max前逐rank检查正有限时长，并核对算子迭代数/预热配置。原来的 `max(正常值, NaN)` 可能隐藏坏rank。已保留此前“排除profile JSON”的文件名修正。
- 修正单节点scale及双节点distributed整步worker：每个step更新后清梯度一次，首次清理在预热前；旧实现每步开头清理、窗口末尾再额外清一次。梯度范数转Python数值放到计时外。仍用本rank墙钟持续时间，结束等待GPU，再由汇总取全rank最大值；不跨主机相减时间戳，不重复乘TP算token数。
- 修正生成器：第二轮 `ARRIVAL_REVERSE=1` 现在同时作用于模型实际执行顺序并写入protocol。旧版本仅反转算子，模型两轮仍是相同的六组位置平衡顺序；旧模型结果没有失去位置平衡，但不能声称第二轮已反序。

这些修改定义了新的计时协议；旧表数值不作“扣除开销”式修补，新协议下所有策略需一起重跑。只改源码不会改变已冻结的二进制和 `outputs/.../e2e-scripts`，必须重新生成脚本快照。

预检通过后，以原始Flux、rank+1基础、交替基础及各自 `+tail` 做五组对照，固定shape、ring_reduction=True、输入与构建选项。另做同样查表路径的恒等表与同窗口随机排列控制，并保留 `--score gap`，分辨时间标签收益、查表成本和局部性变化；这些控制尚未作为额外策略接入现有五组launcher，需单独构建/登记，不能用不同作业的裸中位数相除。

将通过预检的作业目录填入 `PREFLIGHT_DIR`，再启动算子计时：

```bash
PREFLIGHT_DIR="$PWD/logs/a800/arrival/已通过预检的作业号"
sbatch --qos=normal \
  --export="ALL,ARRIVAL_OUTPUT_ROOT=$RUN_ROOT,ARRIVAL_STAGE=operator,E2E_SCALE_PREFLIGHT=$PREFLIGHT_DIR,ARRIVAL_REVERSE=0" \

# 第一轮结束后，使用相同配置且ARRIVAL_REVERSE=1做第二轮。
```

报告两轮各自的配对耗时下降、区间、有效样本数及全部退化shape，叠加必须相对自己的基础计算。若区间持续跨零或重复退化，保留基础策略，先调整标签/局部性/查表开销；不要通过反复选窗口直到“变快”验收。

### T3：按MLP-only范围完成端到端主验收
