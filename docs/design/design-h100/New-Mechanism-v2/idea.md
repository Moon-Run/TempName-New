# MA11 之后：从“选择哪些贡献量化”走向“选择表示、保护误差、复用表示”

更新：2026-10-30。依据新仓库[分析.md](分析.md)、旧仓库 [baseline.md](../../../../../TempName/docs/design/design-h100/New-Mechanism/baseline.md)、MA11 冻结实现与记录，以及截至本日可核验的论文。

**建议研究三个量化机制：①只对确有必要的数据做 Hadamard；②用少量高精度原值修正量化误差，避免整个块退回 BF16；③让一次量化产生的同一份激活贯穿前向 AllGather、前向计算和反向 wgrad。** 第一项先验证“量化能否变便宜”，第二项提高廉价量化的可用范围，第三项把量化覆盖到 MA11 仍然存在的大量前向通信。三者都在完整 MA11 上独立立项，不以叠加未测方案作为基线。

这里提出的是**相对当前项目的新设计与待验证假设**，不声称混合精度、残差补偿或 FP8 AllGather 是首次提出。本文没有实现候选、没有运行新 GPU 实验，也没有测得低于 450 ms 的新结果。与[分析.md](分析.md)中的原生执行计划不同，本次允许改变通信表示及量化误差，因此必须另行验证训练质量，不能继承逐位等价结论。

## 1. 基线告诉我们：缺的不是再省一个小 kernel

### 1.1. MA11 的量化对象和覆盖率

| 项目 | 已有事实 |
| --- | --- |
| 完整 optimizer step | **450.6624015 ms**；同期 MA89 为 459.6383128 ms |
| 工作负载 | H100 80GB、TP8、32 层、H4096、FFN16384、S2048；每步四个 microbatch、8192 token；BF16、无 recompute |
| 已经包含 | MA8-v2 激活复用、MA9 零统计、MA4-F 消费融合、MA11 softmax |
| 实际量化对象 | Attention output 与 MLP FC2 的**前向 GEMM 远端输出贡献**；本地贡献保持 BF16 |
| 选择粒度 | 每个 source 的 128×128 物理 tile；512 个 tile 中 448 个属于远端 |
| codec 粒度 | 每个 token 行内的 128 个 channel；adaptive scale → H128 → quant scale → E4M3 |
| Attention 量化覆盖 | 53 / 3584 个远端贡献，**1.479%** |
| MLP 量化覆盖 | 50 / 3584 个远端贡献，**1.395%** |
| 单组逻辑载荷 | 256 B BF16 → 128 B FP8＋两个 FP32 scale＝136 B |
| 总远端逻辑载荷减少 | Attention **0.693%**、MLP **0.654%**；两角色等权约 **0.674%** |

基线与同期比较见旧仓库 [baseline](../../../../../TempName/docs/design/design-h100/New-Mechanism/baseline.md) 和 [MA11 原始 report](../../../../../TempName/logs/h100/phase6/ma11-v1-causal-softmax-1x-50steps-20261027-121342-060643/fullstep/report.json)。mask 见同批 [selection-plan.json](../../../../../TempName/logs/h100/phase6/ma11-v1-causal-softmax-1x-50steps-20261027-121342-060643/fullstep/scripts/selection-plan.json)，算术见 [taco_codec.cuh](../../../../src/gemm_rs/taco_codec.cuh) 与 [ma2_c_decode.cuh](../../../../tools/h100/phase6/ma2_c_decode.cuh)。载荷比例由选中数量计算，不是 NVLink 硬件计数。

这改变了下一步的研究问题：**当前选择性量化主要通过避免不值得做的 codec 工作改善权衡，尚未形成大范围的通信压缩。** 只加速现有 53/50 个贡献的解码，覆盖面很窄；若新 codec 能使更多贡献满足“传输节省大于编码、解码及误差代价”，才可能打开新的空间。这个“若”需要实测，不代表当前已经证明 codec 是整步瓶颈。

### 1.2. 两条已经做过的路线不能重新命名

- [MA20](../New-Mechanism/ma-20.md) 已经提出全远端候选资格、量化数与生产顺序联合选择、把较重的编码提前。本文不把“扩大预算、重排量化 tile”作为新机制。
- [op4](../到达优先/op-4.md) 已经提出 FP8 fan-in 闭包与变换域合并、共享逆 Hadamard。[实测](../到达优先/base-op4.md)未确认算子收益，且模型数值门禁未通过，正式训练计时为零。本文不重新提出共享逆变换，也不把这个结果泛化成所有新量化路线都不可行。

旧[消融5](../消融实验/base-phase6-ablation5.md)扩大原候选池内的预算没有确认整步收益。因此，仅让更多 tile 使用原 H128/E4M3，证据不足。其短程误差来自固定合成输入，也不能视为真实语料上可任意使用的“精度余量”。

## 2. 共同的设计原则：选择性量化需要第二个坐标

现有选择器主要问：**“这一份贡献是否接近通信拖尾？”** 新机制还应问：**“这份数据用什么表示，才能以最小代价保住对训练有用的信息？”**

对贡献/组 \(b\)，候选表示 \(m\) 有实际编码成本、载荷、解码成本和失真。目标应写成：

$$
\min_{\{m_b\}} T_{\mathrm{step}}(\{m_b\})
\quad \text{s.t.}\quad
\text{预注册的局部失真、梯度和训练质量约束通过}.
$$

不能只最小化字节数，也不能把各块的时间差直接相加。MA11 仍有全 rank publication barrier，producer 编码变重会影响整组可消费时刻；实际目标必须包含 producer、传输、屏障、decoder 和后继消费。

在独立校准中可用以下代理量筛选，再用真实训练确认：

$$
e_b=\hat x_b-x_b,\qquad
D_b=\sum_j h_{\ell,j}e_{b,j}^{\,2},\qquad
h_{\ell,j}=\operatorname{EMA}_{\text{历史校准数据}}
 \left[\left(\frac{\partial L}{\partial x_{\ell,j}}\right)^2\right].
$$

这里 \(h\) 是梯度二阶矩代理，**不是已证明准确的 Hessian，也不是 loss 上界**；当前前向不能预知本次反向梯度。可以从独立样本或已经完成的校准窗口估计，按层/角色/channel 分组冻结，刷新成本计入总训练成本。同时保留未加权 L2、最大误差、p99、零化率等约束，防止代理失效。

多个来源的误差可能相关；归约后的误差也不能假定按 \(\sqrt{7}\) 缩小。必须用实际八来源、原 BF16 舍入顺序测输出。只关注下一层 LayerNorm 也不够：量化误差会进入 residual 支路，不能声称某个被 LN 消掉的方向对整个网络无害。

近期 [Q-PACE（2026-10-06）](https://arxiv.org/abs/2610.09183)用层曲率与量化 MSE 分配训练精度，支持“误差的重要性随层变化”这一研究方向；它主要研究权重量化，本文把评价对象换成 TP 通信贡献、把成本换成完整执行延迟，是需另证的迁移。

## 3. Idea 1：选择性变换——量化不必总经过 H128

### 3.1. 核心变化

**把“BF16 / H128-FP8”的二选一改成“BF16 / 直接块缩放 FP8 / H128-FP8”的表示选择。** 对已经容易量化的组，直接缩放进 FP8；只有直接量化误差不合格、且 H128 的额外成本值得支付时，才做旋转。

量化引入的不只是更短载荷，也引入了一个可选的数据变换。原来每个被选中的块都必须付出 RMS、两级 scale、正逆 H128 的代价；这里把“是否付出这个代价”变成算法决策。它不是换一个更快的 H128 kernel。

对同一 token 内的 \(G=128\) 个 BF16 原值 \(x\)，定义直接量化 D8：

$$
s=\max_j|x_j|/448,\qquad
q_j=\operatorname{E4M3}(x_j/s),\qquad
\hat x_j=\operatorname{BF16}(s\,\operatorname{FP32}(q_j)).
$$

全零组单独编码为零；非零极小 scale 的数值保护必须由独立参考明确，非有限值应报错，不能静默清零当成通过。D8 仍有 amax 归约和类型转换，但没有 H128、逆 H128 和 adaptive RMS scale。H8 则指原有完整 H128/E4M3 codec。

| 表示 | 每 128 元素理想载荷，不含 tag/对齐 | 新增计算 | 适用假设 |
| --- | ---: | --- | --- |
| BF16 | 256 B | 无 codec | 精度敏感或压缩净收益为负 |
| D8 | 132 B | amax、缩放、FP8 转换 | 组内动态范围允许直接量化 |
| H8 | 136 B | 原 adaptive scale、H128、quant scale 及逆过程 | 旋转确能改善失真，且延迟收益仍为正 |

**主要机会是少做正逆变换，132 B 与 136 B 的差别很小。** 不能靠省一个 scale 的 4 B 解释整步大幅提速。实际 tag、对齐和 fallback 都必须重新计入。

### 3.2. 如何作决定

第一版使用独立校准得到的冻结模式表，沿用 MA11 的物理 tile/source 标识和生产顺序：

1. 在真实层输入与不同训练阶段样本上，分别测 D8、H8、BF16 的重建误差和完整消费路径时间。Attention 与 FC2 分开，不从随机矩阵推断真实分布。
2. 先筛掉失真不合格的模式，再选择最快模式；允许 BF16 获胜，不强制某个量化比例。
3. 先在原 MA11 mask 上只替换 codec，回答“D8 是否真的更便宜”。再对额外远端贡献开放 D8/H8 资格，回答“廉价表示是否扩大了有净收益的量化范围”。
4. 模式表可按层/source/物理 tile 冻结，但实时 scale、失真保护和 fallback 必须按**单 token 的 channel 组**计算。跨 token 的实时统计不得决定前面 token 的表示。

若需要在线保护，生产端可在寄存器中用实际 FP8 回转结果检查组内误差，超限后走 BF16。它增加了回转、归约、mode tag 和备用存储开销；先完成选择再远端写，避免先发 FP8 又发 BF16。校准应把这些成本全部包含进去，不能用无保护版本计时、用有保护版本报精度。

接收端先按实际 mode 重建单一来源贡献到 BF16，再沿原来源顺序相加，保留 MA4-F 的 bias/residual 舍入。发布屏障、双槽和本地 BF16 路径沿用。不能把原两个 scale 在实数公式中似乎可约掉，解释成当前 clamp/浮点实现可逐位删除它们。

### 3.3. 论文启发、边界和可否证性

[TACO（2026-04）](https://arxiv.org/abs/2604.24088)研究 TP 中间张量的低幅值集中与 scale/旋转处理；这要求认真检查 D8 的小值零化和长尾误差，不能假定所有块都能跳过 H128。[COAT（ICLR 2025）](https://proceedings.iclr.cc/paper_files/paper/2025/hash/6ac807c9b296964409b277369e55621a-Abstract-Conference.html)采用混合粒度激活量化，启发我们把昂贵表示留给需要它的区域。两篇论文均未验证本文的 MA11 模式选择器。

量化覆盖率为 \(p\) 时，全部使用 D8 的理想远端载荷降幅为 \(48.4375\%\,p\)。例如 \(p=25\%\) 对应 12.109% 的理想载荷下降，远大于当前约 0.674%；**25% 只是敏感性分析的假设，不是预期可用覆盖率，更不是步时预测。**

以下任何结果都能否证该方向：D8 合格组很少；保护开销抵消变换节省；扩大覆盖后 producer/decoder 变慢；字节减少但完整消费路径/完整步时没有改善。不能只报告“删了多少 Hadamard”。

**建议优先级：第一。** 它最直接回答当前选择性量化的核心限制：是否必须用同一个昂贵 codec 才能量化。

## 4. Idea 2：误差修正包——只保护量化真正损伤的信息

### 4.1. 核心变化

**让一个组同时携带 FP8 基础码与少量高精度修正信息。** 一个组若只有少数坐标的量化误差不可接受，无需把全部 128 个元素退回 BF16，也无需必然升级成 H128。

这与 Idea 1 是两个独立维度：Idea 1 选择整个组的变换方式；Idea 2 改变组内部的信息精度分配。它可以单独用固定 D8 基础码实验，通过增加少量修正，把原本不合格的组变得可用。

对实际 D8 回转后的值计算：

$$
e_j=x_j-\operatorname{BF16}(s\,\operatorname{FP32}(q_j)),\qquad
v_j=h_{\ell,j}e_j^2.
$$

选择少量高 \(v_j\) 坐标集合 \(S\)，在 packet 中传它们的**原始 BF16 值**，接收端用覆盖而不是残差相加：

$$
\tilde x_j=
\begin{cases}
x_j,&j\in S,\\
\operatorname{BF16}(s\,\operatorname{FP32}(q_j)),&j\notin S.
\end{cases}
$$

被覆盖位置恢复的是该来源 codec 输入的 BF16 值，不是 FP32 GEMM 精确结果；其后的来源求和仍有原 BF16 舍入。发送 BF16 残差再加回不保证恢复原值，所以首版不采用这种做法。

**选择依据是“量化造成的损伤”，不是单纯的激活幅值。** 大值可能恰好落在 FP8 格点上，小值也可能对损失敏感。也不假定量化误差天然稀疏：必须实测误差贡献是否集中。

### 4.2. 先用固定保护位置，再决定是否值得动态选择

第一版从独立校准数据得到每层/source/channel 组的固定 \(S\)，测试 \(K=|S|\in\{0,2,4,8\}\)。索引存入设备计划表，每次只发送新的 BF16 值，不在热路径执行 top-k。当前数据偏离校准时，按单 token 组误差保护退回 BF16，fallback 率是必须报告的结果。

例如 \(K=4\) 时，可以设计如下固定 packet：

| 区域 | 字节数 |
| --- | ---: |
| 128 个 FP8 基础码 | 128 |
| 一个 FP32 scale | 4 |
| 四个受保护位置的 BF16 原值 | 8 |
| mode/count 与保留空间 | 4 |
| **合计，按 16 B 对齐** | **144** |

固定索引不随 packet 发送，其设备查表和计划存储仍有成本。该设计相对 256 B 的理想载荷减少 **43.75%**；这是一个候选布局，不是原 MA11 已有布局。全 BF16 fallback 必须另有安全槽位，decoder 不得先读未发布的修正值。

若固定保护位置效果不好，第二版才试按本次 \(v_j\) 的阈值做 warp ballot/popc、最多 \(K\) 个例外，超过容量就整组退回 BF16。动态索引、计数和对齐要另算：uint8 index＋BF16 value 是每例外 3 B；bitmap 是每组 16 B＋每例外 2 B。不能拿理想裸载荷冒充实际包大小，也不能忽略写 BF16 备用区的流量。

动态 top-k 只作为离线质量上界：若只有昂贵 top-k 才有效，而便宜阈值/固定位置无效，就不能声称机制可以廉价落地。首版保留基础 D8 scale 的定义；把受保护 outlier 从 amax 中剔除是另一项后续消融，不混入初次验证。

### 4.3. 这种修正为什么可能换来速度

MA11 以整个 tile 为单位选择是否量化；即使只是少量坐标不宜粗量化，也不能只为它们提供保护。修正包把“全组升精度”换成“少量信息升精度”，有机会让更多原 BF16 贡献进入便宜 D8。

例如，把当前 BF16 的一个组换成 144 B 包，理想节省 112 B；若只有四分之一远端数据能这样处理，理想载荷降幅为 10.9375%。但若为计算 \(e\)、查询 \(h\)、筛选位置和回退而增加的成本大于节省，方案就失败。它首先是**改善延迟—失真权衡的假设**，不是无条件的稀疏加速。

固定包让基础码和修正值在同一次 producer 发布中完成；接收端等待整个 packet，再重建和归约。首版不使用“先用低精度算下游、稍后补修正”的异步语义，也不把本次激活误差积累到下一 microbatch。不同 token/样本并非同一个优化变量，DP 梯度 error-feedback 的结论不能直接搬到前向激活。

### 4.4. 与近期论文及既有项目的关系

[ResCom（2026-10-25 预印本）](https://arxiv.org/abs/2610.35955)从激活的 rounding residual 出发，用 output-aware 低秩修正改善量化输出；它启发“补偿量化实际丢失的信息”。[ResQ（ICML 2025）](https://proceedings.mlr.press/v267/saxena25b.html)在不同子空间分配不同精度。两者都是已有的重要思想，不能据此声称本文首创误差补偿。

本文的具体提案是：**用于训练中 TP 远端贡献的、同一次调用内发送的、固定容量原值修正包，并以完整通信路径净延迟约束修正数量。** 它不是 ResCom 的低秩支路，不做跨来源变换域合并，也不重复 op4。

必须报告固定 \(K\) 可解释的误差占比、实际 fallback 率、包大小分布和 codec 延迟。修正单一来源也可能破坏原来的误差抵消，所以还要测实际八来源归约后的误差，不能只看各来源误差下降。如果误差分散、修正位置不稳定、需要过多例外，或训练质量仍不合格，应停止该方向；不能继续扩大 \(K\) 直到包接近 BF16，再保留“高压缩”的宣传。

**建议优先级：第二，与 Idea 1 的精度分析并行。** 若 D8 无保护已经足够，修正包就没有必要；若 D8 只在少数坐标上失败，它才有独立价值。

## 5. Idea 3：一次量化、前后向共用——扩展 MA8 的激活复用

### 5.1. 核心变化

前两项仍处理 row projection 的远端输出。第三项处理 MA11 仍存在的 **QKV/FC1 前向输入 AllGather**，把选择性量化从单次传输策略扩展为激活的生命周期策略。

MA8 已删除对应的反向输入 AllGather，其实现见 [ma8_adapter.py](../../../../tools/h100/phase6/ma8_adapter.py)。不能再次领取删除这 256 次通信的收益。剩余前向 AG 每步仍有 \(32\times2\times4=256\) 次；当前完整 BF16 输入由 autograd context 保留到 wgrad。

新路径如下：

~~~text
本地 LayerNorm 输出 X_s
    → 按 token/channel 组选择 BF16 或量化 packet，一次编码
    → 对 packet 做前向 AllGather
    → 各 TP rank 解出同一份完整 BF16 X_hat
    → Y_r = X_hat W_r^T
    → 保存本次 X_hat
    → backward: dW_r = G_r^T X_hat
~~~

**首版只改变通信表示，GEMM 仍用 BF16，缓存仍保存重建后的 BF16。** 这样一次编码的近似表示同时定义前向计算和反向 wgrad，不需要再次编码/解码，也不改变 GEMM 后端。只有这条路径成立后，才研究直接保存低比特 packet 或 FP8 GEMM，二者都应独立消融。

### 5.2. 必须满足的数值一致性

令 \(X=\operatorname{concat}_s X_s\)，\(\hat X=\operatorname{concat}_s D(Q(X_s))\)。所有 rank 的列分片必须使用**同一个 \(\hat X\)**，包括 source 本地持有的行；不能在 source 使用原 BF16、在其他 rank 使用 FP8 回转值。后者让不同列分片看到不同输入，失去上述统一前向定义。

反向 wgrad 使用前向实际消费的 \(\hat X\)，不能为了“保精度”偷偷恢复原始 \(X\) 算 wgrad。对输入量化使用明确的 STE，dgrad 仍按原 BF16 GEMM 和 ReduceScatter 路径返回；这属于新量化训练语义，不能宣称等于未量化模型的真实梯度。

每次调用保存独立的 \(\hat X\) 与所需元数据，不跨层、跨 microbatch 或跨 optimizer step 复用激活数值。可复用的是**同一个前向实例的表示**及冻结计划，而非前一次样本的内容。

### 5.3. 选择策略与真实字节预算

选择仍需同时满足数值和延迟条件，但新增两个因素：

- **误差的传播对象变了。** column 输入误差 \(E=\hat X-X\) 直接影响 \(EW_r^T\) 和 \(G_r^TE\)；QKV 与 FC1、不同层应分别校准，不能照搬 row 输出的敏感度表。
- **同一次重建结果供 forward 和 wgrad 共用。** 这样避免反向重复 codec；相对原 MA8 仍新增一次编码、解码，不能将其成本自动除以二，也不产生第二次通信删除收益。

首版先以“层/角色”为选择单位，用 BF16 AG 或固定长度量化 AG，避免不同 rank 可变长度包造成额外协商。scale/mode 和 payload 一起用 byte packet 收集，由接收端还原；AG 只搬运数据，无需在 NCCL 中实现 FP8 求和，也无需跨 rank 同步 amax。不同 source 的尺度由自己的包携带。

静态混合布局必须提前为各 source 分配同样的 collective 长度；若为了最长包 padding 后节省消失，就拒绝该配置。在线 BF16 逃逸区也必须计入固定长度。不能在固定长度 AG 中只填写半个 buffer，却按“有效 payload”报告通信减半。若首版采用纯 D8 固定包而无逃逸区，需预先登记严格的失真检查和停止条件，不能允许失败后静默换语义。

在**全部 256 次都能采用 D8、无 header/padding/逃逸区**的理想条件下：

| 单次前向 AG | BF16 | D8，每 128 元素一个 FP32 scale |
| --- | ---: | ---: |
| 本地 256×4096 输入载荷 | 2 MiB | 1.03125 MiB |
| 完整 2048×4096 收集结果 | 16 MiB | 8.25 MiB |
| 理想 ring 每 rank 发送量 | 14 MiB | 7.21875 MiB |
| 256 次累计每 rank 发送量 | 3.5 GiB | 1.8046875 GiB |

这比只优化当前约 1.4% 的 row 量化贡献覆盖更广。表中是算法载荷，不是 NCCL 实际路由计数；其中部分通信可能已被覆盖。不能把[分析.md](分析.md)中的 223.543 ms NCCL AG 累计时间除以二：它混有其他用途、等待和 profiler 扰动。

保持 BF16 缓存的首版**不承诺节省 MA8 激活显存**，量化通信 workspace 反而可能增加峰值。后续若只保存 packet，反向必须再解码一次；只有省下的驻留/读取成本超过新增解码，才值得采用。直接 FP8 GEMM 又涉及 Hopper 的布局、scale 与转置约束，不能把通信 codec 的 H128 系数直接当作原坐标激活参与 GEMM。

### 5.4. 相关工作与本项目可研究的增量

FP8 AllGather 本身已经存在：[Transformer Engine 官方文档](https://docs.nvidia.com/deeplearning/transformer-engine/features/low_precision_training/performance_considerations/performance_considerations.html)明确描述 sequence-parallel 输入/梯度的量化收集，并区分 forward、wgrad 的访问方向。[AGoQ（2026-05）](https://arxiv.org/abs/2605.00539)也研究按层分配激活精度及梯度通信。因此，“把 NCCL AG 改成 FP8”单独不足以成为原创贡献。

值得研究的增量是：**在 MA8 已经保留完整输入的前提下，以 forward/wgrad 共用的重建激活作为一致性约束，按两种用途共同的误差代价和完整训练收益选择哪些层值得压缩。** 如果只得到通用 FP8 AG 的复现，应如实报告为项目增量；只有共享约束/选择方法在同质量下胜过统一 FP8、普通压缩 AG 等对照，才支持更强的研究主张。

**建议优先级：第三，但性能预算比前两项更宽。** 如果只改 row codec 的收益已经接近噪声，优先转向这条仍有 256 次调用的路径。

## 6. 三个机制共有的正确性边界

### 6.1. 不能让量化统计泄漏未来 token

[Breaking Causality in LLM Training with Sparsity and Quantization（EMNLP 2026）](https://aclanthology.org/2026.emnlp-main.2432/)指出，跨 sequence 的共享 scale/mask 可能使早期 token 依赖未来激活，即使 attention mask 仍然因果。

因此三项设计的动态 scale、例外选择和 fallback 都限制在**同一 token 的 channel 组**；若按 128×128 tile 做运行时统一决策，后面的 token 可能改变前面 token 的量化方式。跨 token 的 mode/保护位置只能来自独立数据上的冻结计划，不能读取本次完整 sequence 再决定。

必须做 prefix 检查：保持前 \(t\) 个 token 不变、替换未来 token，前缀的 packet mode、scale、重建值和模型输出应保持原因果语义。该检查适用于模型前向的量化；离线精度校准本身不要求按 token 流式执行。

### 6.2. 分清实现正确性和量化质量

| 验证层次 | 应证明什么 |
| --- | --- |
| codec 独立参考 | 真实 packet 解码符合候选定义；覆盖零值、小值、outlier、边界舍入、tag 与 fallback |
| 通信/生命周期 | 各来源 packet 的 producer/consumer 对 mode 解释一致、无丢失修正、双槽不串数据、存活输出不被覆盖；Idea 3 完整重建输入跨 rank 一致 |
| 局部失真 | 实际八源归约、残差输出及 column 输出/梯度的 L2、最大值、p99、零化率与梯度方向 |
| 训练质量 | 真实语料、相同训练 token/优化器/初始化下，验证 loss、困惑度、梯度稳定性和达到目标质量的时间 |

改 codec 或量化覆盖后，不要求与 MA11 跨臂逐位相同；要求与候选自己的独立参考一致。原 MA11 不受影响的子机制仍须通过原检查。短程 loss 有限和原来的投影 L2≤5% 都不足以证明长期训练质量，不能用宽松局部阈值给三种机制自动放行。

局部阈值、验证集允许退化和停止规则应在性能结果出来前冻结。当前没有真实语料长程数据可据以确定通用阈值；本文不把任意百分比写成已获许可的质量损失。固定合成 microbatch 可继续用于性能复现，收敛评价必须另用独立真实语料。

## 7. 最小实验：先判断机制是否成立，再争取低于 450 ms

### 7.1. 各自保留能解释结果的对照

| 机制 | 必需消融 | 回答的问题 |
| --- | --- | --- |
| Idea 1 | MA11；同 mask 的 D8/H8 替换；同覆盖的统一 H8；冻结表示选择 | 收益来自廉价变换、更多覆盖，还是选择方法本身？ |
| Idea 2 | 同范围 D8；同范围 D8＋固定 K 修正；同范围 H8；扩大范围的修正包 | 修正是否以小成本换来更高可用覆盖？ |
| Idea 3 | MA11；统一量化 AG＋同一重建缓存；按层选择的量化 AG＋同一重建缓存 | 选择策略是否胜过已有通用压缩 AG？ |

对 Idea 2 再比较按 \(|x|\)、未加权 \(e^2\)、加权 \(h e^2\) 选择固定保护位置，检验“误差重要性”是否有额外价值。不同误差质量的组不能只凭速度排序，应比较同质量下的时间或同时间下的质量。

上述消融一次只改变表中因素。最终每个完整候选单独对同期 MA11 做两臂正式训练；三项组合放在单项成立之后，不将单项收益相加。

### 7.2. 计时及预算

沿用现有完整 optimizer step 口径，包含前后向、通信、optimizer 和清梯度；建议每候选至少两个独立 trial，每 trial 八个 AB/BA 平衡块，每窗口 10 步预热＋50 步正式，取八 rank 最大窗口墙钟除以 50，按完整块 bootstrap。不把 50 步或八个 rank 当成独立实验样本，不删除慢窗口。

最终正收益以同期 MA11 配对差值及置信区间判断，历史 450.662 ms 仅作量级参考。若沿用[分析.md](分析.md)的 5% 步时下降目标，需要净省 **22.533 ms/step**，对应历史量级的 **428.129 ms**；本次用户的核心要求是新机制，5% 只是可选进阶目标，不是已经证明可达的承诺。

可用以下关系审视成本，但不能拿它代替计时：

$$
\Delta T_{\rm net}
\approx \Delta T_{\rm exposed\ communication}
- \Delta T_{\rm codec}
- \Delta T_{\rm dispatch/packing}
- T_{\rm refresh}/N_{\rm steps}.
$$

这里各项要按实际依赖路径解释，不能简单由重叠 kernel 的累计时间相减。全部方案都应报告实际 codec 覆盖率、BF16 fallback、含对齐的载荷、编码/解码成本、显存峰值和端到端步时。离线计划成本单列；若持续训练需要定期刷新，刷新时间和额外样本处理必须计入总训练效率。

### 7.3. 实现入口与停止条件

- Idea 1/2 的插入点是 [taco_codec.cuh](../../../../src/gemm_rs/taco_codec.cuh)、[taco_runtime.h](../../../../src/gemm_rs/taco_runtime.h)、[epilogue_evt.hpp](../../../../src/gemm_rs/epilogue_evt.hpp) 与 MA4-F 使用的 mixed decoder 生成链。新 packet 需要独立协议版本和参考实现，不能直接覆盖历史 codec。
- Idea 3 的插入点是 [ma8_adapter.py](../../../../tools/h100/phase6/ma8_adapter.py) 的 column 前向 AG 和 context 保存边界。必须另建候选 adapter；旧 MA11 的源码身份与强检查保留给对照。
- 先做只读激活采样与 codec/误差分布分析，再做真实 producer→consumer 算子实验，最后做完整训练。若 D8/修正包只在离线数据上有效，或计入 codec 后完整路径净收益非正，就停止，不扩大 GPU 正式实验。

**推荐实际推进顺序：先测 Idea 1 的直接量化可用比例，同时用采样数据判断 Idea 2 的误差是否集中；再将通过的表示用于 Idea 3 的前向 AG。** 三条路线分别改变“变换是否必要”“高精度信息放在哪里”“一次量化能被使用几次”，都把新增自由度落在量化本身。
