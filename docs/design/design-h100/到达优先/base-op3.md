# H100 到达优先 op3 v2 实测：扫描拖尾缩短，完整训练仍无收益

更新：2026-10-21。最新回传批次为 `arrival-op3-v2-2x-50steps-20261020-235555-300968`，对应 [op3.md](op3.md) 的v2四组方案及取消性能预筛后的启动器。旧版结果原文已保存在 [base-op3-v1.md](base-op3-v1.md)，不混入本轮配对统计。

## 1. 结论：局部瓶颈改善，但1%目标仍未通过

**O相对本批基线A，两次完整训练分别慢0.928%和0.844%，95%区间均完全落在退化方向。这次没有整步性能收益，也没有达到1%目标。**

- **辅助扫描拖尾确实缩短。** 独立诊断中，仍晚于GEMM结束的调用，其扫描超出时间中位数为Attention **9.760 μs**、MLP **10.783 μs**；v1对应值为209.120/218.527 μs。两者来自不同批次的诊断profile，只支持局部行为改善，不能直接作为训练加速量。
- **提前消费更多、更早。** O的64次profile调用中，**43次**同时满足不同stream重叠和至少一个H128组在本地最后生产发布前完成解码，其中Attention **18/32**、MLP **25/32**。v1为25/64次。
- **完整step仍更慢。** 两次合并的描述性均值为A **537.290 ms/step**、O **542.053 ms/step**，O平均增加 **4.763 ms/step，约慢0.886%**。正式验收仍使用每次独立比较的完整块配对统计。
- **提前消费没有正增量。** O相对同协议串行控制S，两次分别慢 **0.726%**、**0.746%**，两次95%区间均为负。
- **仅换快速解码的D也未验证整步收益。** D/A两次下降率为−0.062%、−0.146%，区间均跨零；不能把D的独立算子加速写成训练加速。

批次正常完成：96个正式窗口、768份正式rank记录、4800个累计optimizer step。`target_validated=false`、`arrival_benefit_validated=false`、`decoder_control_passed=false`，但 `useful_early_consumption_validated=true`。数值和实验完成度检查通过。

已取消的预筛没有拦截本次训练：算子诊断估算节省为 **−8.220 ms/step**，仍继续完成全部训练。该值只是按算子差值外推的分析指标，不是实测step变化，也不是准入门槛。

## 2. 四组对照与计时范围

| 组别 | 发布与消费路径 | 对照意义 |
| --- | --- | --- |
| A | 原生产、整阶段发布屏障、scalar CTA解码、复用屏障 | 本批准确基线 |
| D | 原发布/复用路径，仅换warp H128解码 | 解码优化单独控制 |
| S | 新fragment发布、warp tail，无辅助try | 新协议串行控制 |
| O | 新发布、两轮受限warp try、stop、join、warp tail | 提前消费候选 |

v2保留CTA同步后由leader执行system-release，去掉v1每写线程显式system fence；每轮try为64个CTA，所有轮次合计最多消费1024个不同H128组（总8192组的12.5%）。本地GEMM后发布stop，warp观察到后不再领取下一组；tail按组级done补齐。生产映射、量化数学、ring累加顺序与逐次BF16舍入保持不变；本轮没有重新拟合离线到达排序。

环境仍为 `gxn75` 的8×H100 80GB HBM3、每卡132 SM，PyTorch2.6.0+cu124、CUDA运行时12.4、NCCL2.21.5。四组固定 `CUDA_DEVICE_MAX_CONNECTIONS=8`、`FLUX_GEMM_RS_GEMM_ONLY=1`、`NCCL_NVLS_ENABLE=0`，共用Megatron独立副本及连接数检查补丁。

模型为GPT6.7B，32层、H4096/FFN16384、32heads、序列2048、micro batch1/global batch4、TP8、BF16。每个optimizer step包含4个微批、8192token、Attention/MLP目标投影各128次。每窗口独立初始化，10步预热＋50步正式计时；4800步是多个独立窗口累计工作量，不是一个模型连续训练4800步。

**正式step时间不包含离线准备、编译、预热或独立profile。** 每步实际执行的生产发布、try、stop、stream join、tail与复用屏障开销都包含在内。下文“扫描拖尾”指本次GPU调用中辅助stream晚于本地GEMM结束的时间，不是把离线时间加进训练。

## 3. 完整训练：O/A四轮均退化

两次独立比较，每次12个完整A/D/S/O块，前后各6块且后半反转顺序。每窗口取八rank `elapsed_seconds` 最大值后除以50，覆盖完整前后向、通信、optimizer更新及清梯度；正式计时关闭profiler和诊断时间戳。

“下降率”正值表示更快，负值表示更慢：

| 比较 / 轮次 | A ms/step | D ms/step | S ms/step | O ms/step | O/A配对下降% [95% CI] |
| --- | ---: | ---: | ---: | ---: | --- |
| compare1，第1轮 | 536.536 | 537.505 | 539.331 | 542.730 | -1.154 [-1.575, -0.729] |
| compare1，第2轮 | 538.337 | 538.029 | 537.701 | 542.124 | -0.703 [-1.201, -0.207] |
| compare1，合并 | 537.436 | 537.767 | 538.516 | 542.427 | -0.928 [-1.273, -0.571] |
| compare2，第1轮 | 537.418 | 538.093 | 537.171 | 542.036 | -0.858 [-1.230, -0.524] |
| compare2，第2轮 | 536.870 | 537.769 | 538.155 | 541.321 | -0.829 [-1.075, -0.629] |
| compare2，合并 | 537.144 | 537.931 | 537.663 | 541.678 | -0.844 [-1.066, -0.644] |

下降率为 `100×[1−exp(mean(log(T_candidate/T_baseline)))]`，以完整配对块bootstrap10000次，seed20261020。没有把八rank或窗口内50步当作独立样本。1%验收要求两次比较的O/A点估计和95%区间下界均至少为1%，本次两次均未通过。

| 比较 | D/A配对下降% [95% CI] | S/A配对下降% [95% CI] | O/S配对下降% [95% CI] |
| --- | --- | --- | --- |
| compare1 | -0.062 [-0.334, +0.214] | -0.201 [-0.530, +0.078] | -0.726 [-1.066, -0.398] |
| compare2 | -0.146 [-0.472, +0.186] | -0.096 [-0.372, +0.142] | -0.746 [-1.060, -0.415] |

D/A与S/A两次均跨零，未验证正收益；O/S两次均完全为负，支持提前消费相关路径在本配置下增加了总成本。O/D两次也分别慢0.866%、0.696%，区间均为负。

两次合并、每组24个正式窗口的描述性均值为A537.290、D537.849、S538.089、O542.053 ms/step；A/O吞吐分别约15246.89/15112.92 token/s。全部窗口保留，没有剔除慢样本：按各次、各轮、各组中位数归一化，四组最慢窗口均低于1.009倍中位数。

以本批A均值计算，1%相当于净省约5.373 ms/step；O实际增加4.763 ms/step。这个数量级比较仅用于解释结果，不恢复已取消的算子预筛门槛。

## 4. 独立算子：v2成本大幅下降，但O仍比A慢

算子计时包含6个完整A/D/S/O块、24个fresh-process TP8窗口、192份rank记录。每角色100次预热＋200次正式 `forward().clone()`，取八rank最大墙钟；共9600次正式分布式算子调用，不重复乘rank数。

| 角色 | A μs/次 | D μs/次 | S μs/次 | O μs/次 | O/A配对下降% [95% CI] |
| --- | ---: | ---: | ---: | ---: | --- |
| Attention | 193.603 | 168.156 | 219.312 | 223.156 | -15.265 [-15.702, -14.960] |
| MLP | 268.552 | 242.423 | 300.952 | 303.217 | -12.908 [-13.181, -12.645] |

D/A在Attention上为 **+13.145% [12.779, 13.538]**，MLP为 **+9.729% [9.249, 10.202]**，说明warp解码在这套独立算子条件下有明确收益。但加入新发布/消费协议后，S/A变为−13.278%、−12.064%；再增加提前try后，O/S为−1.754% [−2.355, −1.199]、−0.754% [−1.529, −0.227]。

v1中O的Attention/MLP耗时为531.085/583.342 μs，本轮降到223.156/303.217 μs；这是跨批次的描述性改善，不能代替本批O/A配对。相比当前A，O仍分别增加29.553/34.664 μs。

`micro_savings_estimate`为−8.220 ms，95%区间[−8.326, −8.110] ms。**不能把这个估算当作整步实测退化**：独立重复调用与真实模型的输入、缓存、层间调度及其他工作不同。本轮完整step实际平均多耗时4.763 ms；目前没有正式训练阶段的细粒度trace来精确解释二者差异。

## 5. trace：拖尾改善是真实的，整体收益仍需单独判断

独立profile有32份rank记录、64份trace、256个rank-local调用；其中O为64次。CPU复核按同一次调用匹配GEMM、两轮try、stop、tail和诊断记录，未用其他调用的重叠替代。

| O的诊断 | Attention | MLP |
| --- | ---: | ---: |
| profile调用数 | 32 | 32 |
| 不同stream的GEMM/try存在交集 | 32/32 | 32/32 |
| **同次调用具有有效提前消费** | **18/32** | **25/32** |
| try完全没有消费 | 14/32 | 7/32 |
| try最终达到1024组上限 | 6/32 | 9/32 |
| try最终消费组数，中位数 | 819.5 | 968 |
| 首组完成相对最后生产发布的提前量，中位数（仅有效调用） | 48.656 μs | 73.952 μs |
| 上述提前量范围 | 45.792–55.360 μs | 67.936–89.952 μs |
| 辅助扫描结束晚于本地GEMM的调用数 | 12/32 | 18/32 |
| 超出GEMM结束的时间，中位数（仅超出调用） | **9.760 μs** | **10.783 μs** |
| 超出GEMM结束的时间，最大值 | 12.159 μs | 13.056 μs |
| 扫描超出stop kernel结束的时间，中位数（仅超出调用） | 7.056 μs | 7.696 μs |
| stop时间戳后完成的组数，最大值 | 128 | 216 |

总计128对GEMM/try时间交集，对应43次有效提前完成调用。1024组是整个try最终完成数量上限，不表示这些组全部在生产结束前完成；诊断中stop发布后仍有组完成，也不能把stop理解为所有warp在同一绝对时刻立即退出。

相比v1，Attention有效调用从1/32增至18/32，MLP从24/32变为25/32；发生拖尾的调用数由两角色各25/32降到12/32、18/32，拖尾中位数由约209/219 μs降到约9.76/10.78 μs。**因此旧版“大量辅助扫描工作持续到生产之后”的问题明显缓解，但没有消除join，也没有让整步O/S转正。**

同批profile的kernel耗时中位数如下，均为带诊断的独立算子值：

| 角色 / kernel | A μs | D μs | S μs | O μs |
| --- | ---: | ---: | ---: | ---: |
| Attention GEMM（含编码/发布） | 93.568 | 94.272 | 139.567 | 140.879 |
| Attention 解码 / tail | 48.624 | 26.351 | 58.032 | 48.768 |
| MLP GEMM（含编码/发布） | 153.295 | 154.782 | 208.478 | 207.166 |
| MLP 解码 / tail | 51.391 | 28.736 | 52.207 | 51.168 |

D的解码明显变短，而S/O的生产kernel仍明显长于A/D。这提示剩余瓶颈不只在辅助扫描末尾，还可能包括生产发布成本、新协议等待和运行时调度。**这些profile数值含诊断扰动，各列中位数不能直接相加作为总调用耗时，更不能据此分摊训练中的4.763 ms退化。** 当前没有单独消融把发布、跨rank等待、资源竞争与kernel发起成本精确分开。

所有A/D trace均保留发布和复用两道屏障；S/O只保留最终复用屏障，O每次执行两轮try及一个stop。新路径确实执行，不能再用“仍完全等待整阶段发布屏障”解释本次失败。

## 6. 正确性与复核边界

- 192份算子计时rank记录的 **4608项**输入/输出及独立codec检查通过，覆盖3个seed×4次改变输入/权重复用、重复调用以及rank0/rank7延迟生产；A/D/S/O对应输入和输出哈希逐项一致。
- 模型smoke共32份rank记录、每组512项、合计 **2048项**检查通过。四组最大相对BF16 L2均为2.545994%，最大相对独立codec参考L2均为0.017685%。
- 768份正式训练rank记录的loss/grad_norm检查通过，skip/fallback均为0；所有96条窗口级loss轨迹逐项相同，平均loss为3.821014，最终loss平均为3.261156e−05。这是固定合成数据上的一致性，不是长期收敛验证。
- CPU审计重算算子与完整训练报告，与回传JSON逐项一致；重新解析全部64份trace，profile汇总除迁移后的trace绝对路径外逐项一致。批次状态与重算验收结果一致，五份控制脚本哈希与远端登记一致。
- 审计记录 **1114个输入文件的SHA256**。远端完整构建、动态库和Megatron副本未回传，因此核验的是记录/计划间来源一致性和已回传文件字节，未加载或重新核验缺失二进制。原始实验文件未修改，本机没有重跑GPU实验。

本轮支持的结论是：**v2缩短了诊断中的辅助扫描拖尾，增多了有效提前消费，但O仍可重复地慢于A和S；到达优先带来至少1%完整训练加速的目标仍未实现。** 本次只更新结果，不改参数、不启动新实验。
