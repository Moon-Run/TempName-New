## 3. 测量规模：默认50个正式窗口

每轮5个完整配对块，每块恰好包含五个策略各一次，共两轮：

```text
1种基础 × 5组 × 5块 × 2轮 = 50个正式窗口
50窗口 × 8个rank = 400份正式计时rank记录
每窗口10步预热＋20步完整optimizer step，共1000个正式计时step
```

第一轮冻结一个五策略排列并循环移位，使每组在五个执行位置各出现一次；第二轮反转配对块及块内策略顺序。固定调度seed为20261013，prepare时保存完整调度表。两轮都是前向、反向、通信、参数更新和清梯度的完整训练step，不是第一轮前向、第二轮反向。

保留配置测量块数的能力；如需增加，使用5的正整数倍并在启动前冻结，本方案默认只跑一套50窗口，不自动追加独立复测或因结果不理想重复测量。每轮只有5个配对块，结果解释应结合区间，不把20个step或8个rank当作独立重复样本。

正式计时前，每组各做一次smoke和一次profile：共10个预检窗口、80份rank记录、40份profile trace。四个候选各做映射核验；`native_taco` 按其原生通信路径核验，不要求提供候选tile映射。映射/数值/profile用于确认执行正确，不新增算子性能对照。

监控沿用 [watcher.md](../watcher.md)：每套开始前检查GPU；如采用排队启动，忙时每600秒检查、空闲后每10秒确认，连续3次满足条件才开始。一套预检与正式计时运行中不周期查询GPU占用，禁止在组间或窗口间恢复轮询。这里的“一套”改为本方案五组、50个正式窗口，不能硬套旧六策略72窗口。

## 4. 报告要回答的问题

| 比较 | 可以解释什么 |
| --- | --- |
| G1/G2/G3/G4分别对 `native_taco` | 各组合相对Megatron＋量化基线的总体性能 |
| G2对G1、G4对G3 | 全BF16或定向量化条件下，到达优先的增量 |
| G3对G1、G4对G2 | 到达优先关闭或开启时，选择性量化的增量 |
| G4对G1 | 在交替基础上同时加入到达优先和量化的整体增量 |

本轮没有G0，因此不能单独测出“交替排序相对原始tile顺序”的贡献；没有原生BF16 Megatron，也不能报告相对它的同期加速。G1对 `native_taco` 的差距同时包含共同计算/通信实现和量化方式的差别，不是交替排序独自带来的收益。G4不要求一定最快，负收益与跨零区间照实报告。

每窗口取八rank最大elapsed除以20。逐轮分别列出五组的ms/step中位数及tokens/s，并输出以下两张相对 `native_taco` 的表：

1. **中位加速比表**：`median_b(T_native_taco,b / T_group,b)`。
2. **最好加速比表**：`max_b(T_native_taco,b / T_group,b)`；附对应轮次、block及双方耗时，明确它是最佳单块观测，不是稳定收益。

同时保留原配对耗时下降 `100 × (1 − exp(mean(log(T_group / T_reference))))` 及按完整配对块bootstrap的95%区间（10000次，seed20261009）。轮次分别报告，可另外给出同一会话两轮合并的10块统计；不从历史会话拼接基线，也不自动跨不同实现/环境合并结果。

**主结果保留全样本。** 可另附一套慢窗口敏感性表：按各轮各策略全样本的原始中位数标记超过1.10倍的窗口，只要五组任一组触发，就剔除同一配对块内全部五组；阈值不在筛选后迭代重算。列明剔除块、触发策略和剩余块数，所有组合使用相同保留块；没有剩余块时写“无可用配对块”，不输出伪造的零收益。原始数据不删除，筛选结果不替代主结果。

这是一项简化消融，不套用旧方案“同时对两个必须baseline达到4%”的验收，因为本轮没有测固定Flux融合v2。正确性与数据完整性通过、性能增量是否成立，应分别表述。
