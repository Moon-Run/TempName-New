## 1. 只保留这九组

三种策略定义如下，A/B/C 仅为本方案简称，不复用历史 G1–G6 的编号含义：

| 策略 | 名称 | 交替基础顺序 | 到达优先 | 所选模块的远端贡献 |
| --- | --- | --- | --- | --- |
| A | 仅交替排序＋完整量化 | 开 | 关 | 全部 H128/E4M3 量化 |
| B | 交替排序＋到达优先＋完整量化 | 开 | 开 | 与 A 相同，全部远端贡献量化 |
| C | 交替排序＋到达优先＋选择性量化 | 开 | 开 | 按冻结物理 mask 定向量化，其余 BF16 |

**“完整量化”明确指所选模块前向输出的全部远端贡献量化。** GEMM、本地贡献和未选中模块仍为 BF16，反向沿用现有 BF16/STE 实现；不表示整网 FP8、权重量化或反向梯度量化。“仅交替排序”只说明关闭到达优先，不表示关闭完整量化。

三种策略分别应用于三种模块范围，得到以下九个新策略 ID。它们由新 `ablation3.py` 入口统一展开，不是旧五组/四组 CLI 的新增选项。

| 策略 ID | 简称 | 作用范围 | Attention 输出投影 | MLP 输出投影 |
| --- | --- | --- | --- | --- |
| `interleaved_all_mlp` | A-MLP | 仅 MLP | 原生 Megatron BF16 | A：交替＋完整量化 |
| `interleaved_arrival_all_mlp` | B-MLP | 仅 MLP | 原生 Megatron BF16 | B：交替＋到达优先＋完整量化 |
| `interleaved_arrival_selective_mlp` | C-MLP | 仅 MLP | 原生 Megatron BF16 | C：交替＋到达优先＋选择性量化 |
| `interleaved_all_attn` | A-Attention | 仅 Attention | A：交替＋完整量化 | 原生 Megatron BF16 |
| `interleaved_arrival_all_attn` | B-Attention | 仅 Attention | B：交替＋到达优先＋完整量化 | 原生 Megatron BF16 |
| `interleaved_arrival_selective_attn` | C-Attention | 仅 Attention | C：交替＋到达优先＋选择性量化 | 原生 Megatron BF16 |

| `interleaved_arrival_all_attn_mlp` | B-双模块 | MLP＋Attention | B：交替＋到达优先＋完整量化 | B：交替＋到达优先＋完整量化 |
| `interleaved_arrival_selective_attn_mlp` | C-双模块 | MLP＋Attention | C：交替＋到达优先＋选择性量化 | C：交替＋到达优先＋选择性量化 |

模块边界固定为：

- **MLP**：每层 `mlp.linear_fc2` 的前向 GEMM–ReduceScatter，共 32 个模块；不改 `linear_fc1` 和激活函数。
- **Attention**：每层 `self_attention.linear_proj` 的前向 GEMM–ReduceScatter，共 32 个模块；不改 Q/K/V、QK、Softmax、AV 或 KV cache。
- **MLP＋Attention**：同时启用上述 64 个投影模块；两角色各自使用独立配置、计划和工作区。

本轮只登记这九组。原生 Megatron、原生 Flux、Megatron＋朴素量化、固定融合 v2、全 BF16 消融、随机 mask 和远端优先均不另加测量组。A/B 的完整量化使用候选侧融合 codec，**不是**朴素 `native_taco`，也不是带 CTA 解码和旧封装的固定 `taco_fused`。A 是本轮同作用范围的策略参考，不能称为原生或历史必须 baseline。

## 2. 固定实现与模型输入

三种策略必须从同一版本的候选计算实现派生，保持 GEMM、融合编码、warp 解码、双完整工作区、输出生命周期、模型适配和反向处理一致。A/B 只改变到达置换，B/C 只改变物理量化 mask；不同时调整 tile、stage、解码算法或同步协议。

| 项目 | 固定设置 |
| --- | --- |
| 模型 | GPT 6.7B，32 层、hidden4096、FFN16384、32 heads |
| 设备与并行 | 单节点 8×H100，132 SM；TP8/DP1/PP1/CP1，记录 GPU UUID 及顺序 |
| 输入与 batch | 合成 token，S2048、micro batch1、global batch4，每 step 累计 4 个微批、8192 token |
| 初始化 | seed1234、token_seed4321，配置词表32768、实际 padded vocab33792；九组初始参数/RNG/token 指纹一致 |
| 选中模块 | SM90 编译的候选 GemmV2，BF16 GEMM，H128/E4M3 远端 codec，warp 混合解码及双完整工作区 |
| 未选中模块 | 原生 Megatron BF16 forward，不启用候选替换或通信量化 |
| 顺序 | `interleaved`；A 关闭到达置换，B/C 使用同一角色的同一到达置换 |
| 量化 | A/B 为全部远端物理贡献；C 为每来源最多 1/64 的定向选择，本地 mask 始终为零 |
| 计划窗口 | 同一目标分区的 64 个合法槽位；当前每分区恰有 64 个物理 tile |
| 环境 | 沿用已测 H100 环境及 Megatron 固定版本，实际版本、源码和依赖提交写入 manifest |

未选中模块的原生 BF16 路由需要在九组中保持一致。因此，本轮 MLP-only 不能直接套用历史“Attention 投影仍走 Hopper V3”的旧候选路由，也不能将其历史计时当作本轮的 MLP-only 测量。所有九组均须在新会话重新预检和计时。

共同实现来源以 [候选冻结 manifest](../../../../outputs/h100/phase6/frozen-candidate-v1-20261013/manifest.json) 的已测 `candidate` 字段为起点，并结合已经验证的双 shape 构建与 scope 适配；原候选计算源码提交为 `ff38f5b1ff1c80cb831f58c64b95f42b0379879a`。新会话另外登记实际维护提交、双 shape 适配来源和最终构建哈希，不能用冻结起点提交号代替新库身份。

## 3. 两角色计划与三个开关关系

### 3.1 完整 shape 分派

| 角色 | 全局 `[M,N,K]` | TP8 本地 K | 物理 tile 数/每目标分区 | 每来源远端 tile 数 |
| --- | --- | ---: | --- | ---: |
| Attention | `[2048,4096,4096]` | 512 | 512/64 | 448 |
| MLP | `[2048,4096,16384]` | 2048 | 512/64 | 448 |

Attention 与 MLP 分别使用真实 H100 BF16 校准，不因输出 M/N 相同而共用到达表。设备查表必须区分本地 K，模块适配器同时核对角色与完整 shape；不通过修改 FFN 维度模拟 Attention。

可复用此前真实双 shape 校准，参考 [双 shape 使用说明](../../../../tools/h100/phase6/README-mlp-attention.md) 和 [已回传范围结果](../base-phase6-mlp-attention.md)。复用前核对设备/可见顺序、shape、基础映射、计算来源及计划哈希。若这些身份变化，按原协议重新校准，再由本次同一套角色计划共同派生九组；不为每组分别挑选更有利的计划。

已有实测角色计划示例为：

- [Attention 计划](../../../../outputs/h100/phase6/TTention-MLP-gpt67-tp8-20261014-231236/plans/measured/attn.json)：各来源选择数 `[7,7,7,2,7,7,7,1]`。
- [MLP 计划](../../../../outputs/h100/phase6/TTention-MLP-gpt67-tp8-20261014-231236/plans/measured/mlp.json)：各来源选择数 `[2,7,7,2,7,7,7,0]`。

上述数量用于说明复用来源，不是要求新校准必须得到相同数量。不能混入旧五组所用的另一份 MLP mask；最终采用哪套角色计划须在本轮准备时唯一确定。训练仍为 pass 0/1，pass 2 只诊断，不用于补满选择预算。

### 3.2 到达置换与物理 mask

| 策略 | 到达置换 | 显式物理 mask | 每来源选中数 |
| --- | --- | --- | --- |
| A | 恒等置换，随后执行交替基础映射 | `mask[s,t] = 1` 当且仅当 `destination(t) != s` | 448 |
| B | 冻结角色计划的到达置换 | 与 A 完全相同的全远端 mask | 448 |
| C | 与 B 完全相同的到达置换 | 冻结角色计划的定向 mask | 0–7，按实际准入数量 |

每个 mask 为 `[8,512]`，按 `[source rank, physical tile]` 索引。改变执行槽位不能改变某个物理贡献是否量化。A 的恒等置换是“关闭到达优先”，不是退回原始 Flux 顺序；交替基础始终开启。

同一角色在单模块与双模块范围中复用相同的置换和 mask。例如 B-Attention 与 B-双模块的 Attention 计划必须一致；C-MLP 与 C-双模块的 MLP 计划必须一致。全远端量化以每个来源的全部 448 个远端 tile 为准，不受 C 的 1/64 预算限制；双模块 C 分别对两种 shape 使用预算，不将预算在两角色间转移。

推荐九组共用同一份计算/codec 源码，可分别派生“基础交替”和“交替＋到达置换”两类双 shape 库；B/C 通过显式 `all_remote`/`targeted` mask 共用到达置换库。是否复用已有二进制由接口及哈希核验决定，不要求九套重复编译，也不能只改策略名称而保留旧路由。

## 4. 运行规模：本次一轮81窗口，兼容默认两轮

九组放入同一完整配对块。默认每轮9个块，每块九组各执行一次。轮数在prepare时通过`--rounds {1,2}`选择；本次显式传`--rounds 1`，不传时仍为原两轮：

```text
3种策略 × 3种作用范围 = 9组
本次：9组 × 9个配对块 × 1轮 = 81个正式窗口
81窗口 × 8rank = 648份正式计时rank记录
每窗口10步预热＋20步完整optimizer step，共1620个正式计时step
兼容两轮模式：162窗口、1296份正式rank、3240个正式step
```

第一轮以固定seed20261013生成九策略排列，再循环移位，使每个策略在九个执行位置各出现一次；一轮模式完整保留这一调度。仅两轮模式会追加第二轮，同时反转块及块内顺序。prepare将轮数交叉登记到submission、准备记录和worker配置中；run/report按冻结轮数执行。不能按作用范围先后跑三套互不配对的实验，再将它们当作同场配对。

本次只安排一轮81窗口，不追加第二轮或独立复测，不按结果增减块数。若另行指定更多块，必须在启动前固定为9的正整数倍。旧会话缺少显式轮数字段时按两轮解释，不能截断旧调度将未完成实验改称一轮完成；轮数改变须新建compare。20个step与8个rank不作为独立重复样本；配对比较以完整块为单位。

**所有 ms/step 都是整个 32 层模型的一次完整 optimizer step。** 每步含 4 个微批的全模型前向与反向、相关通信/同步、一次参数更新、学习率调度和清梯度；不能将 MLP/Attention 表头解释为局部层或算子耗时。两轮均按这一范围计时，第二轮反转的是策略执行顺序。

正式计时前，每组各做一次 smoke 与一次 profile，共 18 个预检窗口、144 份预检 rank 记录和 72 份压缩 profile trace。映射与路由应覆盖 **12 个“策略×启用角色”组合**：MLP-only 三项、Attention-only 三项、双模块六项。相同映射可以复用底层检查结果，但每个组合都要登记其预期坐标、mask 与来源，不能省略某角色的验证。

资源检查沿用已有范围实验：每套开始前核对 GPU 身份与占用；运行期间不在组间或窗口间周期查询显存、利用率和计算进程。若后续另行安排外部等待队列，遵守 [watcher.md](../watcher.md)，不由本方案自动启动等待或实验。

## 5. 报告必须回答的问题

### 5.1 同作用范围下的三个主要比较

对 MLP、Attention、MLP＋Attention 分别报告以下三项，共九项主比较：

| 比较 | 配对参考 | 可以解释什么 |
| --- | --- | --- |
| B 对 A | 同范围 A | 完整量化下，开启到达优先的增量 |
| C 对 B | 同范围 B | 相同到达置换下，全远端量化切换为定向选择性量化的净变化 |
| C 对 A | 同范围 A | 在交替＋完整量化基础上，同时引入到达优先和稀疏选择的组合变化 |

C 对 B 同时改变了量化覆盖率、编解码工作量和 BF16/FP8 流量，不能称为“相对不量化的收益”或“定向选择优于随机”。本轮没有全 BF16、匹配随机或关闭到达优先的选择性量化组，不能补推出这些未测因素或完整的到达优先×量化交互。

### 5.2 同策略的作用范围比较

对 A/B/C 各自报告：

- 双模块对 MLP-only：保持 MLP 策略及计划不变，额外将 Attention 从原生 BF16 切换为同策略候选的净变化。
- 双模块对 Attention-only：保持 Attention 策略及计划不变，额外将 MLP 从原生 BF16 切换为同策略候选的净变化。
- MLP-only 对 Attention-only：比较两种应用范围的完整模型 step，明确是不同作用范围的总体差异。

这九项为范围比较，与九项主比较分表展示。不能把双模块与单模块之差解释为另一模块的独立算子耗时，也不能假定两个模块的收益可以相加。本轮没有两模块均为原生 BF16 的组，不能求完整的范围交互或声明相对原生模型的同期加速。

### 5.3 表格与统计口径

每窗口取八 rank 最大 `elapsed_seconds × 1000 / 20`。逐轮列出九组的中位 ms/step 与 tokens/s，吞吐统一按 `8192×1000/(ms/step)` 计算。可以采用下表布局，当前不填写未测数字：

| 策略 | MLP ms/step | Attention ms/step | MLP＋Attention ms/step |
| --- | --- | --- | --- |
| A：交替＋完整量化 | 待测 | 待测 | 待测 |
| B：交替＋到达优先＋完整量化 | 待测 | 待测 | 待测 |
| C：交替＋到达优先＋选择性量化 | 待测 | 待测 | 待测 |

每项比较明确 X 为待比较策略、Y 为参考，使用同轮同块的配对数据：

```text
配对耗时下降(%) = 100 × [1 − exp(mean_b(log(T_X,b / T_Y,b)))]
中位加速比      = median_b(T_Y,b / T_X,b)
最好单块加速比  = max_b(T_Y,b / T_X,b)
```

正下降表示 X 更快，负值如实报告。95% CI 按完整九组配对块 bootstrap 10000 次、seed20261009 计算，九组始终使用同一块的对应记录。最好值附轮次、block 和双方耗时，只表示单块观测；不能用两列中位数相除替代配对指标。

按冻结的实际轮数分别报告，并明确`round_count`及每轮块数。本次一轮为9块，报告的`combined`与第1轮是同一批数据，不额外计样本，也没有第二轮反转验证；两轮模式则另列同一会话合并18块统计。不拼接旧MLP-only、旧四组或旧融合基线耗时作为同期参考。本轮多项比较的区间为逐项区间，未校正多重比较时须标明，不能将某一个有利显著结果推广成九组普遍获益。

**主结果保留全样本。** 可附慢窗口敏感性表：使用每轮各策略全样本中位数的 1.10 倍作固定阈值，九组任一组触发即排除同一块全部九组，所有主比较与范围比较共用同一保留集合；不筛选后迭代阈值。列明触发策略、剔除块及剩余数量；零块时不报收益，一块时只给点估计、不估计区间。原始记录保留，敏感性表不替代主结果。

本轮不套用旧六策略的 4% 验收门槛；数据完整性、执行正确性和性能变化分开判断。A/B/C 不预设快慢顺序，本轮也不能报告相对未测 `native_taco` 或 `taco_fused` 的加速。

必须验证以下内容：

1. **覆盖精确**：定义、构建、prepare、调度、run、预检和 report 只展开表中九组，所有组均为候选策略，不误走旧 native 分支；不隐藏失败组或先执行未登记组。
2. **独立开关**：同角色 A/B 的全远端 mask 相同；B/C 的到达表相同；A 使用交替基础映射。mask 按物理贡献查询，且 A/B 每来源恰好量化 448 个远端 tile。
3. **范围一致**：smoke、profile、预热及 `stop_audit()` 之后的正式计时执行相同路由。MLP-only/Attention-only 各启用 32 个候选投影，双模块启用 64 个；未选中模块是登记的原生 BF16 路径，不算意外 fallback。
4. **调用数与 kernel**：每个启用角色每完整 step 有 `32层×4微批=128` 次调用，20步窗口为2560次，双模块共5120次，按各rank记录核验。profile 按 CPU 角色注解及 CUDA launch correlation 检查对应 V2/codec kernel，不将同名 GPU 镜像注解重复计数，也不硬套旧“Attention必须出现V3”的条件。
5. **实际量化字节**：每个启用角色按来源rank记录 mask、实际选择量及 wire bytes。当前每来源全 BF16 的远端逻辑载荷为 `7×256×4096×2=14680064` 字节；A/B 全量为 `7×256×32×136=7798784` 字节；C 为 `14680064−q_s×128×(256−136)`，其中 `q_s` 是该角色该来源实际选中数。这是一次投影的逻辑载荷，不是完整step硬件链路计数。
6. **生命周期与精度**：角色、模块和双缓冲槽位的 BF16/FP8 工作区不得别名；发布屏障和双缓冲复用依赖保持原样。沿用既有 BF16/独立 codec 参考门槛、有限 loss/梯度、零skip及零意外fallback检查，不把短程通过写成长期收敛结论。
7. **冻结身份**：记录初始化/RNG/token、设备顺序、源码/依赖提交、共同计算源码、每组顺序/角色mask、实际加载库、控制脚本和调度哈希。校准库不能进入正式计时，CPU合成计划不能通过改标记升级为实测计划。
8. **CPU回归与交付状态**：CPU回归覆盖九组集合、一轮81/两轮162窗口与位置平衡、轮数冻结/旧记录兼容、到达/mask同一性、K512/K2048分派、全部scope路由、量化字节、工作区隔离、错误哈希/缺rank/缺窗口/额外轮次拒绝、配对统计及统一整块筛选。默认dry-run不启动GPU；编译通过、GPU正确性和性能测量分别记录。

旧实验入口、固定 `fused_v2` 源码、已冻结的候选源码/库/计划及报告继续保留。实现阶段不夹带新的性能优化，不因新增scope修改模型维度。可执行的 CLI、参数与准备/编译方法已写入 [九组使用说明](../../../../tools/h100/phase6/README-ablation3.md)；真实GPU执行仍需后续明确安排。
