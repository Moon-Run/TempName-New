## 1. 五组的最终定义

所有组都作用于 **MLP＋Attention**：32 个 `mlp.linear_fc2` 和 32 个 `self_attention.linear_proj`，共 64 个输出投影。不新增单 MLP、单 Attention 分组；不量化 QKV、MLP 第一层或整个模型的权重。

按用户确认，“交替＋远端＋完整量化”沿用消融 3 B 组的**到达优先**含义。按随后确认，**Flux、A、B 使用同一固定融合 v2 实现，只有 C 沿用消融 3 双缓冲实现**。

| 组 | 策略 ID | 调度 | 远端量化 | codec / 工作区 / 输出 |
| --- | --- | --- | --- | --- |
| Megatron＋量化 | `native_taco_attn_mlp` | 原生 Megatron GEMM＋张量通信 | 全远端 | Tensor TACO；保留原生 linear forward 与反向，不导入 Flux |
| Flux＋量化（融合 v2） | `flux_fused_v2_attn_mlp` | 原始 Flux 顺序 | 全远端 | 固定 `a800-fused-v2-cta-v1`；单工作区、每次 configure/reset、输出 clone |
| A：交替＋完整量化 | `interleaved_all_attn_mlp` | 基础交替 | 全远端 | **与 Flux 完全相同的固定 codec、单工作区和输出 clone** |
| B：交替＋到达优先＋完整量化 | `interleaved_arrival_all_attn_mlp` | 基础交替＋实测到达表 | 全远端 | **与 Flux/A 完全相同的固定 codec、单工作区和输出 clone** |
| C：完整版 | `interleaved_arrival_selective_attn_mlp` | 与 B 相同的到达表 | 定向选择性量化 | 消融 3 的冻结候选实现：优化 codec、双工作区、实例持有配置与输出 |

“完整量化”指全部远端贡献：每来源 448 个物理 tile；本地贡献保持 BF16。C 的“完整版”指完整算法组合，使用选择性 mask，每来源最多 7 个远端 tile，不表示所有 tile 都量化。五组 GEMM 都保持 BF16，反向沿用既定 BF16/STE 路径。

A/B 仅沿用消融 3 的顺序、到达表和全远端语义，**实现已改为与固定 Flux 对齐**，所以不能把消融 3 的 A/B 实测值直接填进本实验。C 沿用消融 3 的实现与计划；仍需在本次相同环境和完整配对块中重新测量。

## 2. 比较能回答什么

| 主要比较 X/Y | 解释范围 |
| --- | --- |
| Flux / Megatron | 固定融合实现相对原生 GEMM＋张量量化通信的整步差异 |
| A / Flux | 同一融合 v2 实现下，原始顺序改为交替顺序的净变化 |
| B / A | 同一融合 v2 实现及全远端量化下，增加到达优先的净变化 |
| C / B | 选择性量化和完整候选实现共同带来的净变化；包含 codec、双缓冲、配置及输出生命周期差异 |

报告同时提供五组全部 10 项配对比较，包括 A/B/C 对 Megatron 和 Flux。**C/B 不是仅切换选择性 mask 的严格单因素消融**；不能把全部差值归因于选择性量化。没有预设 4% 收益门槛，负收益和跨零区间照常保留。

## 3. 固定模型、实现与构建隔离

模型沿用 GPT6.7B：32 层、H4096、FFN16384、32 heads、S2048、micro batch1/global batch4、TP8/DP1/PP1/CP1、BF16、seed1234、token_seed4321，padded vocab33792。Attention 完整 shape 为 `[2048,4096,4096]`、本地 K512；MLP 为 `[2048,4096,16384]`、本地 K2048。两种 shape 都执行融合量化 V2；不是把 Attention 留在原生 Hopper V3。

计时为**完整 optimizer step**：4 个微批的全模型前向/反向、通信、更新、调度和清梯度，8192 token/step。新建会话每个正式窗口先预热 10 步、计时 60 步；`ms/step = max(8 rank elapsed_seconds) × 1000 / 60`。smoke/profile的原预检步数不变。不以局部 GEMM 或某个 rank 的时间代替完整 step。

准备器在submission及preparation快照中冻结 `execution_timing={warmup_steps:10,timed_steps:60}`，worker读取 `scripts/config.json`，严格报告核验60步轨迹及每投影240次正式调用。原构建和 `submission.config` 的20步字段保留构建身份，执行与统计使用独立的 `execution_timing`，无需重编译库。旧会话缺少该新字段时，报告仅按原冻结的20步核验/统计；新复测脚本拒绝接受20步会话，不能直接修改旧compare配置重跑。

构建生成四套独立运行库，每套均支持上述两种 shape：

```text
build/
  fused/taco_fused/                 # 原始 Flux 融合 v2
  fused/interleaved_all/            # A：同 codec，只改交替映射
  fused/interleaved_arrival_all/    # B：同 codec，只改到达映射
  candidate/scope-candidate/        # C：冻结双缓冲实现
  plans.json                       # 同一双角色校准派生的 A/B/C 计划
  ablation4-manifest.json
```

构建与报告核验 Flux/A/B 的全部源码哈希，允许变化的文件只有 `threadblock_swizzle.hpp` 和 `phase6_host.hpp`。固定六份 kernel/codec/frontend 源码须匹配仓库中的 [融合 v2 冻结来源](../../../../tools/h100/phase6/fused_v2/README.md) 及既有 H100 适配。A/B 设备与主机映射按完整 shape 分发；B/C 采用同一角色到达坐标表。C 来源仍为冻结 `frozen-candidate-v1`，父 commit `ff38f5b1ff1c80cb831f58c64b95f42b0379879a`。

Megatron 固定 commit `3ea68ad6042cc1204386ae9364358f7c4de1bc37`。量化 Flux 路径使用 SM90 编译的 GemmV2；kernel 注册名含 `sm80` 是算法键，不代表复用 A800 cubin。构建、采样、运行和报告都保留独立身份与哈希。

## 4. 75 通信配置

本实验默认 `prepare --nvls-enable 0`，校准入口也默认关闭 NVLS，与 75 已通过的通信路径一致。原因与历史证据见 [75 NCCL 诊断](../diagnose-gxn75-nccl.md)。这不是声称 74 原来也是 0。

prepare 冻结全部当前 `NCCL_*`、`TORCH_NCCL_*` 和 `GLOO_SOCKET_IFNAME` 环境变量；明确设置 `NCCL_NVLS_ENABLE=0`、`NCCL_DEBUG=WARN`，去掉 `NCCL_DEBUG_FILE` 和 `NCCL_DEBUG_SUBSYS`。同时登记 `/etc/nccl.conf`、`~/.nccl.conf` 及显式 `NCCL_CONF_FILE` 的内容哈希。已有 IB、网卡等设置会保留并写入快照，不自动把其他容器的 `bond0/mlx5` 配置套到当前容器。

每个 worker 使用同一冻结环境，在 CUDA 初始化前检查环境与配置文件；每份 rank 记录、command 和最终报告记录通信配置。后续 shell 中临时 export 的 NCCL 值不会覆盖会话配置，配置文件变化则拒绝运行。需改变通信设置时新建 compare。`--nvls-enable auto` 仅表示不写环境变量覆盖，NCCL 配置文件仍可能指定该值；它不代表保证启用 NVLS。主实验五组不能混用两种配置。

## 7. 调度、预检与报告

**默认测一次就是一轮，不是两轮**：1 轮×5 个五组完整块＝25 个正式窗口，每组测 5 个窗口。`run --stage all` 表示运行预检和全部已登记计时窗口，不会自动增加第二轮。固定 seed20261013 打乱组顺序后循环移位，每组在五个位置各出现一次；`--blocks` 必须为 5 的正整数倍。显式 `prepare --rounds 2` 才是两轮、50 个正式窗口，第二轮反转块顺序和块内顺序。轮数与调度在 prepare 时冻结。

| 设置 | 正式窗口 | 正式 rank | 正式计时 step | 含预检的 worker 窗口 |
| --- | ---: | ---: | ---: | ---: |
| 默认 `--blocks 5 --rounds 1` | 25 | 200 | 1500 | 35 |
| `--blocks 5 --rounds 2` | 50 | 400 | 3000 | 60 |

两种模式均额外有 10 个 smoke/profile 窗口、80 份预检 rank、40 份压缩 profile trace、8 项策略/角色 GPU mapping。每个模块拥有独立实例；Flux/A/B 检查单 packet 工作区，C 检查两个 packet/mask 工作区；跨模块地址不得别名。预检检查两个角色实际关联的 V2/解码 kernel、完整 shape、调用次数、量化字节、BF16 与 codec 参考误差。正式窗口要求八 rank 齐全、零 skip/fallback、有限 loss/梯度、相同初始化/RNG/token/运行库指纹、通信快照和正确调度。

报告输出 `report.json` 和 `report.md`：

- 全样本平均/中位 ms/step、`8192000 / 平均 ms` 的 tokens/s；逐轮和 combined 均给出。单轮 combined 与第 1 轮是同一批样本。
- 10 项同块配对比较：`100 × [1 − exp(mean(log(T_X/T_Y)))]`、完整五组块 bootstrap10000 次的 95% 区间（seed20261009）、中位加速比及最好单块。
- 慢窗口敏感性附表：各组本轮中位数×1.10，任一组触发即排除整块五组，阈值不迭代；全样本仍是主结果。

八 rank 和窗口内的60个step不当作独立样本；逐项区间不作多重比较校正。缺少 rank、缺失/额外窗口或预检证据变化都会拒绝出具完整报告。回传后可用 `report --offline` 核验保存的文本与哈希；它不声称重新读取 75 的实际动态库。短程合成 token 的正确性和耗时不代表长期收敛。

## 9. 原 75 执行方案：两次实验，每次两轮

用户确认的“两次”是两个独立实验，不是每个实验四轮。每次 prepare 使用 `--blocks 5 --rounds 2 --nvls-enable 0`。第一次有 round1/round2，第二次也有自己的 round1/round2；每次第二轮同时反转第一轮的**块顺序和块内五组顺序**，模型仍正常执行前向、反向和更新。两次共享通过身份核验的校准计划与四套运行库，各自新建 run_id、调度、预检与报告。

| 范围 | 正式窗口 | 正式 rank | 预检窗口 / rank | profile trace | mapping |
| --- | ---: | ---: | ---: | ---: | ---: |
| 每次实验：2 轮 | 50 | 400 | 10 / 80 | 40 | 8 |

宿主服务中的 Docker 客户端保持前台连接，以便服务记录这两次实验的退出状态；容器中的实际进程由 Docker 创建，应另外核对控制器 PID 和祖先进程/cgroup。若本机 Docker 不在 `/usr/bin/docker`，先用 `command -v docker` 确认后替换。服务的独立环境不会继承 Codex shell 的临时 export；容器脚本恢复登记的运行环境，CUDA/Python 路径显式传入，NCCL 环境由冻结的 compare 配置应用。`active (exited)` 表示程序退出后保留服务状态；应结合退出码和两套严格报告判断完成。
