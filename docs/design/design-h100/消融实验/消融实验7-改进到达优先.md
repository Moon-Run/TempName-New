更新：2026-10-19。本实验按 **C、A、B（改进版）** 三组对比，覆盖32个Attention输出投影和32个MLP输出投影。C保留原实现和原到达表，选择性量化预算改为 **1/16**；A保留原方案，只有B使用改进的到达调度。三组统一每窗口 **预热10步、正式计时50步**。本文集中保存机制分析、改进方案和比较口径；消融4保留原实验定义与历史结果。

2026-10-19回传的两次3＋3批次分别停在消融6生成器编译、旧校准源码证据解析阶段，均未开始消融7。两处已修复，本地失败会话目录按要求清理；原因与重新启动方法见[消融6文档第9—10节](消融实验6-对比baseline.md)。校验现在可读取旧计划已登记且哈希精确匹配的原控制器副本，当前改进到达调度代码继续用于新B；本页C/A/B定义及3＋3调度不变。

## 1. 三组定义

| **C：完整版（选择性量化）** | **A：交替＋完整量化** | **B：交替＋到达＋完整量化（改进版）** |
| ---------------: | ------------: | --------------------: |
| 原完整版实现：交替＋原到达表＋按1/16预算生成的选择性mask | 保留原交替顺序，不增加到达重排 | 在与A相同的交替顺序上使用改进到达调度；无可靠信号时保持原序 |
| 原候选优化codec、双工作区、实例持有配置与输出 | 固定融合v2、单工作区、逐次配置/复位、输出clone | 与A使用完全相同的codec、工作区和输出生命周期，仅映射不同 |
| 远端量化预算上限1/16＝6.25%，每来源最多28/448个远端tile | 每来源448个远端tile全部量化 | 每来源448个远端tile全部量化 |
| 原角色到达表保持不变；1/16的实际mask独立生成并冻结，不随B重新拟合 | identity映射，即基础交替顺序 | `tail_residual`，方法标识 `receiver-tail-residual-v1` |

“完整量化”仍仅指远端来源贡献，本地贡献保持BF16；不是整网权重或GEMM低精度化。三组GEMM及既定反向路径保持原BF16/STE语义。

**本实验中的B始终指改进版B。C不自动替换为新到达表。** C的算子实现、工作区和到达表沿用原完整版，仅将量化预算从1/64提高到1/16，并重新生成实际mask；重新测量的是该预算下的同场完整step性能。若后续也将新排序应用到C，应另行明确为“改进版C”，不能混入本次三组定义。

C的预算参数为 `fraction=0.0625`，每来源448个远端tile的选择上限由7个提高到28个。应使用原校准pass0/1的同一评分与选择规则重新生成两角色mask，并登记实际选择数及mask哈希；可以少于28个，不要求用满预算。本地贡献仍禁止量化。不能只改预算字段却继续使用旧1/64的mask；历史1/64性能及覆盖率也不能作为本次C的实测值。

## 3. 旧到达优先为什么收益不明显

历史依据为[消融4的60步总结](base-phase6-ablation4.md)：旧B/A的两次配对耗时下降为−0.185%、−0.135%，区间均跨零。代码和profile审计表明，主要问题是**离线生产顺序重排的优化目标，与整组barrier之后才消费的路径不匹配**，并非到达表开关未生效。

- 两次compare的A/B mapping均显示：Attention改变2491/4096个物理坐标（60.815%），MLP改变2422/4096（59.131%）；接收目标槽位序列完全相同。表实际参与调度，但不能改变目标之间的交替频率。
- [融合v2 wrapper](../../../../tools/h100/phase6/fused_v2/src/gemm_rs/ths_op/gemm_reduce_scatter.cc) 在GEMM后先调用 `forward_barrier()`，再启动 `taco_decode_reduce()`。H100量化适配统一选择V2，因此这道barrier实际执行。
- 两次compare的A/B、rank0/rank4共8份trace中，**2048次投影全部按同一CUDA stream上的 `GEMM → barrier → decode → barrier` 串行执行，GEMM/decode重叠为0次。** 提前产出部分tile不能让消费者提前工作；可争取的是生产阶段尾部缩短，而非逐tile流水线重叠。profile绝对耗时受profiler扰动，不用于推算正式step收益。
- [旧评分](../../../../tools/a800/arrival/plan.py) 对两遍训练中稳定接近最晚的来源，按receiver相对起点的tile到达时间赋分。本批 `window=64`，覆盖整个目的地的64个tile。评分混合了原排位导致的晚到和独立处理/传输延迟，也没有计算被后移tile是否形成新尾部。BF16校准标签用于全远端量化B，还存在执行路径差异。

这些证据不能证明所有到达感知调度都不可行。当前codec的发布与工作区复用依赖同步，不能仅删除barrier就声称实现了流水线。真正的就绪驱动归约需另行实现fragment/epoch发布、可见性及复用协议，并经过八卡验证；本次先改进现有离线调度的决策规则。

## 4. 改进B：去除排位趋势，保守优化尾部

实现位于 [arrival_tail.py](../../../../tools/h100/phase6/arrival_tail.py)，通过 [plan.py](../../../../tools/h100/phase6/plan.py) 的 `arrival_order='tail_residual'` 接入现有物理映射生成流程。

1. 按“来源、接收目标、窗口、训练pass”独立进行非降保序回归（PAVA），把到达时间拆为原排位趋势和残差。只在同一接收目标内部建立代理，不比较不同GPU的绝对时钟。
2. 用“目标槽位趋势＋该tile残差”预测交换后的完成时间。提前tile、被后移tile和其余tile全部计入窗口最大值；pass0、pass1都必须降低尾部，且改善超过该pass最大观测误差的6倍，才接受交换。
3. 每窗口最多4次交换，保留destination/window边界和一一映射。观测缺失、仅有单调排位延迟、两遍不一致或改善不足时，使用identity，即A的基础交替顺序。
4. pass2不参与排序或接受决策；它在冻结顺序上重新估计自身PAVA趋势，仅用于诊断，不是时延模型的样本外性能验证。

B仍量化全部远端贡献，不能用降低量化覆盖率制造调度收益。C继续使用原到达表，mask按1/16预算独立生成。新方法诊断、源码哈希、完整shape和输出映射须随B计划冻结。

逻辑slot不等于CUDA实际执行时刻，不同tile也来自不同采样调用。PAVA是候选生成模型，6倍门槛只覆盖观测误差代理，不覆盖模型失配。本版还会放弃需要联合交换才能改善的并列尾部；某来源窗口改善也未必改变整组关键路径。是否提速最终由同codec、完整step的B/A实测决定。

## 6. 三组同场实验口径

沿用原模型条件：单节点8×H100 80GB、GPT6.7B、32层、H4096/FFN16384、32 heads、S2048、micro batch1/global batch4、TP8/DP1/PP1/CP1、BF16、seed1234、token_seed4321、padded vocab33792。Attention完整shape为 `[2048,4096,4096]`、本地K512；MLP为 `[2048,4096,16384]`、本地K2048。

每窗口先预热10步，再正式计时50步，共执行60个optimizer step；预热不计入正式耗时或loss统计。每步4个微批、8192 token，每窗口正式计时409600 token。完整step包含前向、反向、通信、optimizer更新、调度及清梯度，窗口耗时为 `max(8 rank elapsed_seconds) × 1000 / 50`。三组统一冻结 `execution_timing={warmup_steps:10,timed_steps:50}` 及通信配置，含 `NCCL_NVLS_ENABLE=0`，并核验初始化、输入、角色shape、量化模式及运行库身份。

正式窗口每rank应有50项loss/grad_norm，每个输出投影应有200次正式前向调用（50步×4微批）。一个完整三组块包含150个正式optimizer step，另有30个预热step；总步数由执行前冻结的块数、轮数和独立实验次数决定。

每个完整块包含C、A、B各一个窗口。各组在块内位置均衡，块数取3的正整数倍；第二轮反转块顺序和块内顺序。**默认 `--blocks 6 --rounds 2`：每轮6个完整三组块，共36个正式窗口、1800个正式optimizer step。** 每组12个窗口、600个正式step。额外有6个smoke/profile窗口、48份预检rank、24份trace和6项角色mapping。执行前冻结轮数、块数、运行次序、独立run_id和计划哈希；C、A、B均在本次会话重测，不直接复用历史计时值。

主比较B/A及辅助比较C/A、C/B使用同轮同块配对。下降率为 `100 × [1 − exp(mean(log(T_X/T_Y)))]`，正值表示X更快；置信区间按完整三组块bootstrap计算。八rank和窗口内50个正式step不当作独立样本。保留负收益与跨零区间，主表保留全部正式样本。
